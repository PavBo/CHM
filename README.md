# ЧСЛ — Человеческая слот-машина (MVP)

Финальная тестовая сборка 1.0.0 адаптивного веб-приложения с серверной логикой турниров. В сборку включён специальный одиночный тестовый режим: автоматически поддерживается расписание примерно на один час, взнос составляет 10 Gold Coins, минимальное число участников — 1, а старты идут каждые 2 минуты. Первый тестовый турнир создаётся примерно через минуту после запуска чистой среды. Это позволяет одному пользователю пройти полный цикл: регистрация → участие → обычный спин → финальный остаток → итоговая таблица.

## Запуск

Требуется Node.js 18+.

```bash
npm start
```

После запуска открыть: `http://localhost:4173`

Для входа в админ-панель используйте Username `Admin`.


## Финальный одиночный тестовый режим

При чистом запуске backend автоматически создаёт тестовый шаблон и период:

- взнос: **10 Gold Coins**;
- минимум участников: **1**;
- максимум участников: 40;
- комиссия для этого тестового шаблона: 0%;
- выплаты обычных линий: 1 / 1 / 1 Gold Coin;
- турнир каждые **2 минуты**;
- период: примерно **1 час** (31 турнир);
- первый турнир появляется примерно через **1 минуту** после запуска среды.

Такие турниры отмечаются в пользовательском списке меткой **«можно одному»**. В админ-панели также есть кнопка **«Создать тестовый период»**, которая полностью пересоздаёт пустую будущую часть этого тестового расписания. Уже начатые или уже занятые турниры не меняются. Для будущей производственной версии автогенерацию тестового режима можно отключить переменной окружения `CHSL_SOLO_DEMO=0`.

## Что реализовано

- простая регистрация и вход по уникальному Username;
- 10 000 Gold Coins при регистрации;
- доступный и зарезервированный баланс;
- таблица «Действующие / Где я участвую / Прошедшие»;
- подтверждение участия и резервирование взноса;
- защита от повторного и параллельного списания при запросах из нескольких вкладок/устройств;
- уникальный аватар каждого участника внутри турнира;
- автоматический серверный старт турнира по каноническому времени `startAt`;
- регистрация закрывается строго в `startAt`; короткое серверное окно фиксации старта сохраняет приоритет административной отмены, если она приходит на самой границе старта; во время этого окна пользователь видит состояние «Запускается»;
- если backend был недоступен в момент старта, после восстановления он продолжает турнир с нужной текущей фазы, а не с нуля;
- единый серверный RNG-результат для всех зрителей; выбор участников выполняется сервером через `crypto.randomInt`;
- независимый равновероятный выбор участника для каждого из 9 мест обычного спина;
- сохранение последовательности спинов и продолжение того же турнира после перезапуска backend;
- обычный спин разделён на серверные фазы: 4 секунды вращения, 2 секунды результата, 1 секунда паузы; выплата фиксируется на границе результата после 4 секунд;
- финальный спин занимает 5 секунд, после чего фиксируется остаточная выплата;
- сервер как единственный источник времени, с периодической синхронизацией клиента;
- синхронизация просмотра через Server-Sent Events;
- при временном разрыве SSE клиент переходит на резервное периодическое обновление, а после восстановления соединения возвращается к потоку;
- при возврате во вкладку или восстановлении сети открытый турнир принудительно синхронизируется с backend;
- во время фазы вращения backend не отдаёт клиенту будущих победителей или выплаты текущего спина; клиент показывает синхронную временную прокрутку, а фактический результат раскрывается только в разрешённой фазе;
- поле 3×3, где выплата каждой строки начисляется каждому из трёх игроков строки;
- один пользователь может появляться в одном спине несколько раз;
- комиссия `floor(общий взнос × процент / 100)`;
- финальный спин остатка на центральном барабане: 3 случайных участника, выигрывает центральный;
- автоматическое начисление выигрышей независимо от присутствия пользователя;
- результаты всех участников, включая 0 Gold Coins, с сортировкой по выигрышу;
- автоматическая отмена при нехватке минимального количества участников;
- ручная отмена администратором с возвратом резерва; если отмена приходит на границе автоматического старта, она имеет приоритет и турнир не успевает списать взносы, начислить комиссию или создать спины;
- отдельный накопительный учет комиссии платформы без повторного начисления после перезапуска;
- административная проверка целостности: резервы, баланс банка, уникальность номеров и аватаров, учет комиссии;
- создание, изменение и деактивация шаблонов турниров;
- снимок параметров шаблона в уже созданном турнире — последующие правки шаблона его не меняют;
- создание периодов расписания: шаблон + начало + конец + количество турниров;
- автоматическая генерация указанного количества турниров в периоде;
- редактирование расписания целиком: пустые ещё не зафиксированные турниры пересоздаются по новой конфигурации независимо от их даты, а уже начатые турниры и турниры с участниками остаются неизменными;
- отдельный сгенерированный турнир нельзя редактировать вручную;
- ручное создание турнира администратором;
- административная карточка турнира со снимком параметров, участниками, экономикой, количеством спинов и журналом операций;
- административный дашборд с количеством пользователей/турниров, резервами и накопленной комиссией;
- адаптивный интерфейс desktop / tablet / mobile, повторяющий композицию, цвета, размеры блоков и иерархию Figma;
- локальный логотип и слот-машина на hero-блоке, восстановленные из предоставленного Figma-референса;
- набор из 9 базовых портретов из предоставленного Figma-референса с детерминированными цветовыми вариациями, позволяющими сохранить уникальность аватаров до 96 участников;
- временный космический фон турнира, сгенерированный локально в стилистике Figma из-за недоступности исходного фонового ассета;
- визуально переработанные состояния ожидания, проведения и финального розыгрыша; бизнес-логика от визуального слоя не зависит, поэтому временный фон можно заменить оригинальным ассетом без переделки механики.
- финальный розыгрыш приведён к Figma-сценарию: боковые колонки приглушены, на центральном барабане остаются три участника, после раскрытия центральная карточка победителя получает золотую рамку и свечение, а весь остаток показан как отдельная Gold Coins-плашка.
- мобильная версия дополнительно проверена на viewport 390×844: hero, список турниров, статистика, игровое поле 3×3, финальный розыгрыш и итоговая таблица не требуют горизонтальной прокрутки и сохраняют визуальную иерархию desktop-версии.
- подтверждение участия приведено к отдельному Figma-сценарию с ярким временным prize-wheel visual и центральной карточкой подтверждения;
- итоговая таблица приведена к Figma-структуре: тёмный фон, заголовок, две колонки и строки 64 px;
- админ-панель визуально унифицирована с пользовательской частью: логотип, темные карточки, Gold Coins-акценты, градиентные CTA и адаптивная сетка.

## Важная реализационная договорённость по расписанию

Исходный документ требует задавать «количество турниров за период», но не определяет точные моменты внутри периода. В этой версии турниры распределяются **равномерно** между началом и концом периода. Расписание редактируется только как единый объект. При изменении уже зафиксированные турниры (начавшиеся либо имеющие участников) не меняются, а пустые ещё не зафиксированные турниры пересоздаются по новой конфигурации. Администратор может задавать прошлое, текущее или будущее время — сервер не накладывает ограничение «только будущее». Отдельное ручное редактирование сгенерированного турнира отсутствует.


## Подготовка к размещению по публичной ссылке

В корне проекта добавлены готовые конфигурации для внешнего хостинга:

- `render.yaml` — Render;
- `railway.toml` — Railway;
- `Dockerfile` — универсальный контейнерный запуск;
- `Procfile` — совместимый fallback для платформ, использующих Procfile;
- `/api/health` — health-check endpoint, возвращающий версию приложения и серверное время.

Приложение использует переменную `PORT`, которую большинство хостингов передаёт автоматически. На тестовом развертывании `CHSL_SOLO_DEMO=1` включает согласованное одиночное расписание. Локальная JSON-база создаётся при первом запуске. Для долговременной производственной эксплуатации её следует заменить на транзакционную БД или подключить постоянный диск; для демонстрационной ссылки текущего механизма достаточно.

## Проверка

```bash
npm test
```

Основной интеграционный набор проверяет health-check релиза 1.0.0, регистрацию, регистронезависимую уникальность username, уникальность аватаров, повторное и параллельное резервирование, возврат при ручной отмене, приоритет отмены на границе старта при уже закрытой регистрации, автоматическую отмену при недоборе минимального числа участников, ограничение вместимости, фазу результата после 4 секунд, случай точного расходования банка без финального спина, обычный и финальный спин, центрального победителя финального барабана, присутствие участников с нулевым выигрышем в итоговой таблице и её сортировку, округление и накопительный учет комиссии, административный аудит, детальную карточку турнира, деактивацию шаблонов, уникальность номеров турниров, неизменяемость созданного турнира после изменения шаблона, серверное время, скрытие исхода спина до фазы результата, генерацию и целостное редактирование расписания с сохранением уже зафиксированных турниров, отсутствие future-only ограничения для административных дат, параметры одиночного тестового расписания и полный сквозной проход одиночного турнира до финального баланса.

Отдельный restart-тест поднимает backend несколько раз на одной базе и проверяет, что сохранённая RNG-последовательность не меняется, пропущенные по времени спины корректно догоняются, а комиссия платформы не начисляется повторно.

```bash
npm run test:all
```

Тесты используют ускоренный коэффициент времени только внутри тестового процесса. При обычном `npm start` применяются согласованные реальные интервалы 4 + 2 + 1 секунды и 5 секунд для финального спина.

## Структура

- `server.js` — HTTP API, хранение данных, турнирный движок, SSE-синхронизация;
- `public/index.html` — пользовательское приложение;
- `public/app.js` — пользовательские сценарии;
- `public/styles.css` — адаптивный UI;
- `public/admin.html` — админ-панель;
- `public/admin.js` — логика админ-панели;
- `tests.js` — основной набор интеграционных тестов;
- `tests-restart.js` — отдельный тест восстановления турнира после рестарта backend;
- `data/db.json` — создаётся автоматически при первом запуске.
